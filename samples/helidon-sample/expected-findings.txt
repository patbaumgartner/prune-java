# Ground truth for the prune-java integration tests: a Helidon SE application.
#
# Format: <verdict> <type> <symbol>
#
#   unused     prune-java must report exactly this set of (type, symbol) pairs.
#              SampleProjectFixtureTest asserts set equality, so a missing or an
#              extra finding fails the build.
#
#   test-only  Not reported by default, because a test references the symbol.
#              With test references excluded it is reported with exactly this
#              type and the message says so.
#
#   kept       prune-java must never report this symbol, under any type. A false
#              positive that deletes live code is the worst failure mode this
#              project has. The type column names the guard that keeps the
#              symbol when explanations are requested, or ANY when the symbol is
#              referenced by an identifier and never reaches a guard.
#
# Helidon SE is plain Java: no annotations, handlers wired by method reference.
# The build has a module-info.java, so no UNUSED_VISIBILITY finding is possible;
# the module's exports decide visibility, and GreetingCodes shows the guard.
# MetricsExporter is loaded by name from application.yaml.
